# ALangEngine模块迁出计划

## 1. 迁出模块清单

根据Technical\_Preference.md和Todo文件，我将按照以下顺序迁出非std包下的模块：

1. **xml** - XML处理模块
2. **yaml** - YAML处理模块
3. **os** - 操作系统交互模块

## 2. 迁出方案

### 2.1 通用迁出步骤

对于每个模块，我将执行以下步骤：

1. **创建目录结构**：在AsulModule文件夹下创建对应的目录，例如AsulModule/Xml
2. **创建头文件**：创建{package\_name}.h文件，声明模块的初始化函数
3. **创建实现文件**：创建{package\_name}.cpp文件，实现模块的功能
4. **更新ALangEngine.cpp**：

   * 在全局作用域包含新创建的头文件

   * 在installBuiltins函数中调用模块的初始化函数
5. **更新CMakeLists.txt**：添加新创建的cpp文件到源文件列表
6. **编译验证**：使用cmake --build build -j$(nproc)编译项目
7. **功能验证**：运行functest.sh脚本验证模块功能

### 2.2 具体模块迁出计划

#### 2.2.1 xml模块

* **目录结构**：AsulModule/Xml

* **文件**：AsulModule/Xml/xml.h, AsulModule/Xml/xml.cpp

* **功能**：XML解析和生成

* **验证**：运行Example/xml\_yaml\_example.alang测试

#### 2.2.2 yaml模块

* **目录结构**：AsulModule/Yaml

* **文件**：AsulModule/Yaml/yaml.h, AsulModule/Yaml/yaml.cpp

* **功能**：YAML解析和生成

* **验证**：运行Example/xml\_yaml\_example.alang测试

#### 2.2.3 os模块

* **目录结构**：AsulModule/Os

* **文件**：AsulModule/Os/os.h, AsulModule/Os/os.cpp

* **功能**：操作系统交互，包括命令执行、环境变量操作等

* **验证**：运行相关测试脚本验证功能

## 3. 验证方法

1. **编译验证**：使用cmake --build build -j$(nproc)编译项目，确保没有编译错误
2. **功能验证**：运行./functest.sh脚本，确保所有测试通过
3. **示例验证**：运行相关示例文件，确保模块功能正常

## 4. 注意事项

1. **保持现有用法不变**：确保Example/xxx.alang文件的现有用法不需要修改
2. **一个一个包迁出**：避免错误累积，方便修改
3. **验证每个模块**：在迁出每个模块后，立即编译和测试，确保功能正常
4. **保持代码风格一致**：遵循现有代码的风格和命名约定

## 5. 预期结果

* 所有非std包下的模块成功迁出到AsulModule文件夹

* 编译成功，没有任何错误

* 运行functest.sh脚本，所有测试通过

* Example/xxx.alang文件的现有用法不需要修改

这个计划将确保模块迁出过程顺利进行，并且不会破坏现有功能。
